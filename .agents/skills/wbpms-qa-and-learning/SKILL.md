# WBPMS QA, Testing, Codebase Learning & Multi-Agent Attribution Skill

Use this skill for every engineering, debugging, testing, or handover task in `c:\xampp\htdocs\wbpms`. Always obey the top-level guardrails in `AGENTS.md`.

## Reference Files (Load On Demand)
- [Multi-Agent Modification, Integration & Fix Ledger](./references/agent-work-ledger.md) — Detailed chronological record of work by Antigravity and peer AI agents, plus entry format.
- [Codebase Learnings & Empirical Gotchas](./references/codebase-learnings.md) — Verified doc-vs-code mismatches, schema/PDO pitfalls, PHP runtime notes, and regression TC mapping.

## Workflow 1: Learn from the Codebase Before Editing

1. Inspect `AGENTS.md` (always loaded) and check `git status --short` + `git diff --stat` to see uncommitted work by the owner or other AI agents.
2. Consult [references/codebase-learnings.md](./references/codebase-learnings.md) for known gotchas in the module you are touching (e.g., `HY093` PDO parameters, `SpecialNonWorking` holiday type, decoupled `work_schedule` templates, `Formatter::escape()`).
3. Trust live PHP code in `app/`, `routes/web.php`, and `database/migrations/` over prose in `docs/` if they disagree, and report any mismatch to the user.

## Workflow 2: Unit, Integration & Static Analysis Verification

### Step 1: Identify Available PHP Runtime
In Windows XAMPP environments, `php` and `composer` may not be on the default `PATH`:
- XAMPP binary: `C:\xampp\php\php.exe` (currently PHP 8.2.12 — works for `php -l`, PHPStan, and `regression/generate_regression_tests.php`, but **cannot** run PHPUnit 12, which requires PHP >= 8.3).
- Check for a PHP >= 8.3 binary before running PHPUnit:
  ```powershell
  php -v
  ```
  If `php` is missing or `< 8.3`, report the exact PHP version blocker clearly and run all compatible checks (`php -l`, PHPStan, regression generator).

### Step 2: Syntax Lint All Touched PHP Files
```powershell
C:\xampp\php\php.exe -l <path/to/ModifiedFile.php>
```

### Step 3: Run PHPUnit Unit Suite (Requires PHP >= 8.3)
```bash
vendor/bin/phpunit --configuration phpunit.xml --testsuite Unit
```
- Unit tests live in `tests/Unit/` (20 test classes; pure PHP, no database required).
- When fixing a domain/service bug or adding pure logic in `app/Domain/` or `app/Application/`, add a corresponding unit test in `tests/Unit/` covering both happy path and failure/boundary cases.

### Step 4: Run PHPUnit Integration Suite (Requires PHP >= 8.3 + MySQL `wbpms_test`)
1. Ensure test DB migrations are current:
   ```bash
   vendor/bin/phinx migrate -c phinx.php -e testing
   ```
2. Run integration tests:
   ```bash
   vendor/bin/phpunit --configuration phpunit.xml --testsuite Integration
   ```
3. **Mandatory Skip-Count Audit**: `tests/Integration/IntegrationTestCase.php` marks the suite **skipped** (not failed) if `wbpms_test` is unreachable. Always inspect the summary line and report `Tests, Assertions, Failures, Errors, Skipped`.
4. New integration tests must extend `Wbpms\Tests\Integration\IntegrationTestCase` so each test executes inside an isolated rolled-back transaction.

### Step 5: Run PHPStan Level 6
```bash
vendor/bin/phpstan analyse --configuration phpstan.neon
```
- Covers `app/` (excludes `app/Infrastructure/Reports`). Must introduce zero new errors.

## Workflow 3: Regression Testing & Workbook Maintenance

WBPMS maintains a 157-case regression suite generated by `regression/generate_regression_tests.php` into `regression/WBPMS_Regression_Test_Suite.xlsx`.

1. **Map Changed Modules to Regression TC IDs** (see full table in [references/codebase-learnings.md](./references/codebase-learnings.md)):
   - Auth/Session/CSRF: `AUTH-001..017`
   - Dashboards: `DASH-001..005`
   - Users: `USER-001..009`
   - Employees: `EMP-001..010`
   - Schedules/Holidays: `SCH-001..008`
   - Attendance: `ATT-001..015`
   - Requests: `REQ-001..015`
   - Payroll: `PAY-001..016`
   - Salary: `SAL-001..006`
   - Benefits/Deductions: `BEN-001..010`
   - Reports/Slips: `REP-001..019`
   - Employee Portal: `PORT-001..010`
   - Cross-cutting/Security/System: `SYS-001..017`
2. **Add/Update Regression Cases**: Whenever you fix a bug or change behavior, check if an existing TC covers it. If not, add a new row to `$cases` in `regression/generate_regression_tests.php` following the exact 11-element tuple format.
3. **Regenerate the Regression Workbook**:
   ```powershell
   C:\xampp\php\php.exe regression/generate_regression_tests.php
   ```
   Confirm stdout prints the updated test case count, module count, and file size for `regression/WBPMS_Regression_Test_Suite.xlsx`.
4. **Report Regression Impact**: List every impacted TC ID and whether it was verified via automated PHPUnit tests, manual check, or flagged for human execution.

## Workflow 4: Record AI-Attributed Work & New Learnings

Before completing any task that changes code, tests, migrations, or docs:
1. **Update `AGENTS.md` Section 1**: Add a concise row with `Date`, your exact `AI Name`, `Type` (`Modification` | `Integration` | `Fix`), `Files / Scope`, `Summary`, and `Verification`.
2. **Update [references/agent-work-ledger.md](./references/agent-work-ledger.md)**: Append detailed change notes, affected regression TC IDs, and command outputs/status. Rotate rows out of `AGENTS.md` if `AGENTS.md` grows past 20 ledger rows or 18 KB.
3. **Update [references/codebase-learnings.md](./references/codebase-learnings.md)**: If you discovered a new root cause, schema rule, runtime quirk, or doc-vs-code drift, append a 4-field learning entry (`Symptom`, `Root Cause`, `Resolution`, `Prevention Rule`) tagged with your AI name and date.
